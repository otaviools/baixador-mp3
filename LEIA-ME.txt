COMO RODAR
==========

1. Instale as dependências (uma vez só):
   pip install -r requirements.txt

2. Rode o servidor:
   python app.py

3. Abra no navegador:
   http://localhost:5000

4. Cole o link do YouTube, escolha a qualidade e clique em "Converter para MP3".
   O navegador vai perguntar onde salvar o MP3 (ou salvar direto na pasta
   de Downloads padrão, dependendo da configuração do seu navegador).
   O arquivo NÃO fica salvo dentro da pasta do projeto -- ele é gerado
   numa pasta temporária do sistema. Depois de salvo, ele continua
   disponível por 2 minutos (para o player da página continuar tocando)
   e então é apagado. Arquivos convertidos e nunca salvos são apagados
   depois de 30 minutos.

5. Para parar o servidor: Ctrl+C no terminal.

DICA: se quiser que o navegador SEMPRE pergunte onde salvar (em vez de
ir direto para a pasta Downloads padrão), ative essa opção nas
configurações do navegador:
   Chrome/Edge: Configurações > Downloads > "Perguntar onde salvar cada arquivo"
   Firefox:     Configurações > Geral > Downloads > "Perguntar onde salvar cada arquivo"

OBSERVAÇÕES
===========
- Precisa do FFmpeg instalado no sistema (você já configurou isso).
- O servidor roda só na sua máquina (localhost) -- ninguém de fora acessa.
- Use apenas para conteúdo que você tem direito de baixar.

ESTRUTURA DO PROJETO
====================
- app.py: só as rotas HTTP (Flask).
- converter/: regras do backend (config, jobs, youtube, conversion).
- templates/Index.html + templates/partials/: uma parte Jinja por seção da página.
- static/css/: um arquivo por seção, carregados na ordem da cascata.
- static/js/App.js: ponto de entrada; lib/ (utilidades) e components/ (cada parte da tela).
- tests/: testes do backend (o yt-dlp é simulado, não precisa de internet).

CONVENÇÕES
- Arquivos do front-end (JS, CSS, templates) em PascalCase; módulos Python em
  minúsculas, como pede a PEP 8.
- Nomes no código (variáveis, funções, classes, arquivos) em inglês.
  Comentários e docstrings em português, assim como o que a pessoa vê
  (textos da tela, mensagens de erro) e os dados: rotas e campos da API
  (/api/baixar, qualidade, erro, status) e o histórico salvo no navegador.
- Prints do site: pasta docs/screenshots/ (aparecem no README do GitHub).

TESTES
